# Colour Science Reference

This document describes the colour science theory and implementation behind
the Shade Sayer colour processing pipeline.

## Colour Spaces

### CIE XYZ (sensor native)

The TCS3530 sensor outputs raw tristimulus values that approximate the CIE
1931 2° standard observer X, Y, and Z colour matching functions.  XYZ is a
device-independent, linear colour space.

* **Y** corresponds to luminance (brightness).
* **X** and **Z** encode chromaticity.

### CIE L\*a\*b\* (matching & processing)

L\*a\*b\* is a perceptually uniform colour space where equal numerical
distances correspond roughly to equal perceived colour differences.

* **L\*** — lightness (0 = black, 100 = white).
* **a\*** — green (−) to red (+).
* **b\*** — blue (−) to yellow (+).

Conversion uses the CIE D65 standard illuminant as the reference white
(noon daylight, ~6504 K).

### CIE LCH (saturation enhancement)

LCH is the cylindrical form of L\*a\*b\*:

* **L\*** — lightness (same as L\*a\*b\*).
* **C\*** — chroma (colourfulness / saturation).
* **h** — hue angle (0°–360°).

Used internally for the adaptive saturation enhancement stage.

### sRGB (display/reference)

Standard RGB with D65 white point, gamma ≈ 2.2.  Used only for output
references (e.g. the GUI swatch preview and serial SCAN responses).

## CIEDE2000 Colour Difference

CIEDE2000 (ΔE₀₀) is the industry-standard perceptual colour difference
metric.  It improves on earlier ΔE formulas by adding corrections for:

1. **Lightness weighting** (SL) — humans are more sensitive to lightness
   differences in dark colours.
2. **Chroma weighting** (SC) — sensitivity varies with saturation.
3. **Hue weighting** (SH) — sensitivity varies with hue angle.
4. **Hue rotation** (RT) — compensates for the "blue shift" region
   around 275° where human perception is less uniform.

### Perceptual Meaning of ΔE₀₀

| ΔE₀₀ | Perception |
|-------|------------|
| < 1.0 | Not perceptible by the human eye |
| 1–2 | Perceptible through close observation |
| 2–10 | Perceptible at a glance |
| > 10 | Colours are more different than similar |

The implementation is in `color_math_delta_e_ciede2000()` (see
`color_math.cpp`).

## VP-Tree Fast Matching

A Vantage Point Tree (VP-Tree) partitions the colour space such that a
nearest-neighbour search requires only O(log n) distance calculations
instead of the O(n) required by a linear scan.

* For the 949-colour xkcd database the VP-Tree performs ~12–20 CIEDE2000
  calculations per query.
* The tree is pre-computed at build time by `scripts/generate_vptree.py`
  and stored as a `constexpr` array in `vptree_data.h` (~11 KB Flash, zero
  heap allocations).
* The Kona reference table uses a second VP-Tree generated by
  `scripts/generate_kona_table.py`.

## Colour Processing Pipeline

The `color_pipeline_identify()` function runs a 13-stage pipeline:

### Stage 1 — Raw Sensor Read

Multiple TCS3530 measurements are captured and averaged.  Saturated
readings (analogue or digital) are discarded.

### Stage 2 — Responsivity Normalisation

Raw ADC counts are converted to responsivity-normalised values using the
TCS3530 datasheet constants, accounting for the configured gain and
integration time.

### Stage 3 — Colour Correction Matrix (PCCM)

A 3×10 polynomial CCM (or 3×3 linear CCM) maps sensor XYZ into a
calibrated colour space.  The matrix is determined during the guided
calibration procedure and stored in NVS.

### Stage 4 — IR Compensation

Infrared light leaks into the X, Y, Z channels.  The compensation step
subtracts a fraction of the IR channel reading (scaled by per-channel IR
factors) to remove this cross-talk.

### Stage 5 — Integration Time Normalisation

Readings are normalised to a 100 ms baseline integration time so that
calibration parameters remain valid across different exposure settings.

### Stage 6 — Black Level Subtraction

Residual sensor offset (stray light, LED reflections, electronic noise) is
removed using the dark-reference measurement captured during calibration.

### Stage 7 — White Balance (Chromatic Adaptation)

A Bradford chromatic adaptation transform maps the measured illuminant
white point to D65.  The pipeline maintains separate LED and ambient white
balance profiles so that the user does not need to recalibrate when
switching between illumination modes.

### Stage 8 — XYZ → L\*a\*b\*

Standard conversion using D65 reference white.

### Stage 9 — Lightness Correction

Non-linear gamma correction with piecewise support (separate curves for
dark and light tones) plus a configurable transition point.  Includes a
blue-channel specific compensation.

### Stage 10 — Saturation Enhancement

Adaptive chroma boost in LCH space.  The boost factor is scaled by match
confidence so that high-confidence Kona matches retain their reference
colour while uncertain matches receive a perceptual lift.

### Stage 11 — Kona Reference Lookup

VP-Tree search against the Kona reference table.  If the best match is
within the configurable ΔE threshold (default 5.0), the Kona colour name
and stored description are used.

### Stage 12 — xkcd Fallback Matching

If no Kona match is found (or the table is invalid), the xkcd VP-Tree is
searched.  The closest named colour and its ΔE are returned.

### Stage 13 — Description Generation

A natural-language description is generated from the L\*a\*b\* values,
including hue name, tone descriptor, and saturation qualifier.  If a Kona
match was found, the stored swatch description is used instead.

## Material Correction

Different surface materials (fabric, metal, paper, plastic) reflect light
with different spectral characteristics.  The pipeline applies per-material
L\*, a\*, b\* scaling and offset corrections.  Material can be set
explicitly or auto-detected from sensor statistics (variance-based
heuristic).

| Material | L\* scale | L\* offset | a\* scale | b\* scale |
|----------|----------|-----------|----------|----------|
| Fabric | 1.10 | +2.0 | 1.05 | 1.05 |
| Metal | 0.90 | 0.0 | 0.95 | 0.95 |
| Paper | 1.00 | 0.0 | 1.00 | 1.00 |
| Default | 1.00 | 0.0 | 1.00 | 1.00 |

## Confidence Scoring

Match confidence uses quadratic scaling:

```
confidence = 1 - (ΔE / ΔE_max)²
```

where ΔE_max is the pipeline's maximum acceptable distance for the match
tier (Kona real, Kona synthetic, or xkcd).  A confidence below 0.5
suppresses the colour name for non-Kona matches, indicating the result is
uncertain.
